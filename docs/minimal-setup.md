# 4 个并发槽位，最多 8 次调用

这是手工会话或宿主 agent 工具的运行配方，无 API 依赖。它不包含自动运行的多 agent 调度器。需要能创建彼此独立上下文的实例；宿主不支持时，报告独立性缺口。

## 示例：正确性约束下优化排序

目标不是“运行最快”，而是“返回正确升序列表后再比较速度”。先复制 [任务契约](../templates/records.md)，固定输入集与基准。下表中的“调用”指一次实例工作请求，后续追问和重试同样计数。

| 阶段 | 新调用 | 累计 | 并发 | 输入边界及产物 |
|---|---:|---:|---:|---|
| 首轮探索 A/B | 2 | 2 | 2 | A 从算法不变量出发，B 从性能测量出发；分别产出证据卡 |
| 新综合实例 S | 1 | 3 | 1 | 读两组产物，交换最多各 2 条线索 |
| A/B 各续跑一次 | 2 | 5 | 2 | 接收显式种子，保留各自方法；各提交候选及复现材料 |
| 新技术验证实例 V | 1 | 6 | 1 | 检查候选的正确性，正确后再比较同环境性能 |
| 新对齐实例 R | 1 | 7 | 1 | 核对用户目标及 V 报告 |
| 预留 | 最多 1 | 最多 8 | 1 | 用于某一项缺失检查；不保证足够修复并重新双重审查 |

至少 5 个不同实例 A/B/S/V/R，峰值并发仅 2，适用于 4 槽位环境。四类角色不等于总共四个实例。如果预留预算不足以重新验收修复后的候选，就交付未完成结论及原因；不能拿旧版本的通过记录替代。

V 可以在一次有界调用内验证多个候选，但应优先进行便宜的否证检查。预算不足覆盖全部候选时，清楚标出检查范围。总时间例设 30 分钟：探索各轮约 5 分钟、综合约 3 分钟、验证和对齐各约 6 分钟，剩余缓冲；这是调度起点，宿主超时能力不足时人工停止。

## 目录

```text
run/
  contract.json
  groups/a/
  groups/b/
  synthesis/seeds.yaml
  verification/
  alignment/
  checkpoint.json
  final.md
```

初轮只让 A/B 读取契约和各自目录；S 读两个目录；下一轮由协调者显式发种子；V/R 只接收各自需要的材料。共享文件系统上的路径约定本身不能强制隔离，必要时使用宿主沙箱或分开的工作区。

## 有意义的验收

如果 A 给出 `return input`，已排序样本上测试可能全绿。V 应加入 `[2, 1, 2]` 等反例，并检查结果是否为 `[1, 2, 2]`。R 要确认“快速”未替代“正确升序”。该例展示验收机制，不是本仓库已经完成的排序性能实验。

最终报告允许写“没有候选通过验证”。不把共识、调用量或演示成功当成研究成果。

## 用编排器跑同一套流程

上面的表格是手工会话配方。要检查受管理的路径访问、预算准入和双重审查记录，用仓库内的编排器（无第三方依赖、不联网、不调用任何模型）：

```bash
python3 -m orchestrator selftest            # 校验五条不变量；全绿退出 0
python3 -m orchestrator demo                # 端到端跑一遍本页的验收场景
python3 -m orchestrator run --contract templates/contract.example.json --run-dir run/manual
python3 -m orchestrator status   --run run/manual
python3 -m orchestrator checkpoint --run run/manual
python3 -m orchestrator prompt --role technical_verifier --method invariant-first
```

`demo` 会把本页讲的三件事实际演一遍，而不只是打印说明：探索组 A 读 `groups/b/` 被**拒绝**；候选 `A-v1` 在 `[2, 1, 2]` 上被**否证**；用单份通过的审查或过期版本哈希晋升候选时被**拒绝**。它不思考——模型由宿主提供，编排器只负责让越权和不合格被发现。

`run` 只初始化契约与检查点，不启动模型或执行研究。上面的命令可从干净克隆的仓库根目录直接执行；JSON 示例可按任务修改，每个新实验使用新的 `--run-dir`，避免覆盖已有状态。人工 YAML 记录模板不能直接传给该 CLI。

实测范围与局限见 [验证记录](validation.md)；`orchestrator` 是路径白名单，不是安全沙箱，子进程检查与主进程同权限。
