# 来源与方法边界

来源：[OpenAI — On the Navier–Stokes Millennium Prize Problem](https://openai.com/index/navier-stokes-solution/)，发布于 2026-09-08（页面另注 2026-09-10 更新）。核对日期：2026-09-12。以下只整理工作组织方式，不评判数学结论。

## 原文事实摘要

以下为页面自述，不代表本仓库独立验证了其研究结果：

**方法论相关**

- 该结果由一个**协调 agent 系统**产生，agent 由内部模型驱动，可读缓存互联网并运行代码。
- agent 被划分为**若干组，组内可通信**；各组规模不等；产出 Navier–Stokes 结果的那一组约为 **10,000 个并发 agent**。
- 对每个问题，**不同组收到问题陈述的不同变体**，覆盖全部变体；避免只喂一种表述。
- Navier–Stokes 的“证明”型变体 A/B 与“反证”型变体 C/D **分给不同组**。
- 来源系统先解了一批“更容易”的问题，其中一个成功结果是无外力 Euler 正则性问题，由**约 100 个 agent 协作约 50 小时**产出。
- 看到 Euler 结果后，系统**把其他千禧年问题的 agent 调过来**，并以 Euler 结果作为提示投入 Navier–Stokes。
- 训练持续进行，**新的模型版本可用后 agent 被升级**到该版本。
- 各组被鼓励探索多样方法，之后用 **Codex 跨组综合**，把各组最有用的洞见合并成后续提示；这些提示基于 agent 自己的中间结果。
- Navier–Stokes 结果在首批 agent 启动后**约 88 小时**得到；Lean 形式化与验证**另用约 17 小时**（经 GPT‑6 Astra）。
- 所有问题合计 **490 万条消息、约 3,000 亿输出 token**；其中 Navier–Stokes 为 **270 万条消息、约 1,300 亿输出 token**。
- 全程维持与所有前沿模型评估相同的**监控与隔离**措施。

**溯源与责任相关**

- 该工作是听到传言后启动的，随后得知传言与 Anthropic 的 Levent Alpöge 和 NYU 的 Tristan Buckmaster 有关；对方的并行工作是无外力之外的 **forced Euler** 结果。
- 双方在各自结果完成后才互相看到对方工作；页面称**未访问特定用户数据**来解题。
- 经调查，Buckmaster 此前两个月的 Codex prompts **不可能影响该系统**（包括通过训练）。
- 页面明确表示**不打算凭此结果认领千禧年奖**，并把该成果描述为“进展的一个快照，而不是终点”。

**页面自述的定位**

页面同时提出研究结果并报告模型进展。本仓库处理的是这份工作**如何被组织**，不处理数学结论是否成立——那是数学界的事，与本仓库的主张无关。

## 公开信息的缺口

以下内容**页面没有披露**，本仓库不做推测，也不填补：

- 完整分组策略、组大小分布、精确组间通信拓扑（页面已说明按问题变体分组及组内通信）；
- 角色划分与提示词原文；
- 交换/综合的频率、每次交换的信息量与停用条件；
- 预算分配与停止规则；
- 小规模下的效果对照——即多 agent 相对单 agent 的成本效益；
- 调度器实现、代码、可复现的最小配置。

因此本仓库的九模式命名、四类角色、参数默认值（组数、每次 2 条线索、连续 2 轮无新证据则停用、预算一半给探索等）都是**作者归纳的设计建议**，不是 OpenAI 的参数，也不构成对其系统的复现。要复现工作量级，需要的是数据中心级资源，而不是一份提示词。

## 本仓库映射

| 模式 | 对应原文事实 | 本仓库增加的操作设计 |
|---|---|---|
| P1 双向对冲 | A/B 与 C/D 分给不同组 | 支持证据与反例的通用任务契约 |
| P2 难度阶梯 | 先做 Euler，再以该结果作提示攻 Navier–Stokes | 简化条件及迁移门槛记录 |
| P3 种子注入 | agent 的中间结果被用于后续提示 | 种子证据卡与状态标签 |
| P4 动态再配置 | 其他千禧年问题的 agent 被调来 | 保留挑战路径、只用有效证据调度 |
| P5 分组隔离 | 分组、组内通信、每组一种变体 | 方法分工与最小读取边界 |
| P6 交叉授粉 | Codex 跨组综合最强洞见 | 交换数量、时机、停用条件 |
| P7 底座热升级 | 新训练版本可用后升级 agent | 检查点格式与对照检查 |
| P8 验证闭环 | Lean 形式化与验证阶段 | 技术验证和目标对齐拆为两个实例 |
| P9 溯源护栏 | Concurrent work 与影响调查 | 来源与派生链记录 |

## 证据等级说明

- 规模、时程、token 数、分组方式和跨组综合：**原文直述**，可引用。
- 九模式分类、四类角色、所有参数默认值、降级映射表：**本仓库建议**，未经最优性实验。
- 「对齐审查」这一门：**本仓库独立设计**。原文的 Lean 验证解决的是形式化命题的正确性，不解决“形式化的命题是否等于原始意图”；本仓库据这一差别增设了独立的对齐审查，不把它归因于原文或外部质疑。
- 效能主张：**无**。本仓库提供工作流程，不提供任何“多 agent 优于单 agent”的实验结论。

如需声称方法有效，应增加固定任务、固定成本的单 agent 对照、多次重复运行及独立验收。参见 [验证记录](../docs/validation.md) 了解当前版本的实测范围与局限。
