# 运行中的决策

这是本仓库的操作建议，不是来源系统披露的调度算法。只读取当前任务需要的部分。

## 派发前算清整数预算

每次实例工作请求计一次，包含追问、失败调用、综合和审查。被准入器拒绝而未启动的请求不计调用；宿主实际启动后失败的请求仍计入。已有付费授权不等于无限费用授权，金额与 token 上限须由宿主另行计量，本包的 Ledger 不实现这两项上限。

- 5 次调用：A/B 独立探索 2 次，S 综合 1 次，V/R 审查 2 次；无续跑或修复额度。
- 8 次调用：按最小教程执行 7 次，保留 1 次；不能承诺一次额度足够修复并重验。
- 少于 5 次：若仍要求两条探索路径与四类独立角色，报告预算不足；可交付未验证探索结果，不把同一实例换角色记成独立审查。

每轮先预留 V/R 两次调用，再扣除综合与该轮各组续跑成本。不足以完成整轮就提前收口。取消在途任务不代表费用归零；未知用量写 unknown。调用数、实例总数、峰值并发分别记录。

## 交换线索时保持证据身份

为每条线索记录唯一 ID、来源组、证据位置、适用条件、状态、接收组与派生候选。默认每组每轮最多两条；同一原始证据被多个 agent 引用仍只算一份。

只有各组完成首轮有界产物后才考虑交换。综合者优先选择可验证、与接收组方法互补的线索；没有有用线索可以不交换。保留相互矛盾的条件，不以多数意见裁定。

例：A 在已排序列表上支持候选，B 在 `[2, 1, 2]` 上找到反例。先比较任务输入范围：若契约允许未排序输入，反例否证该候选；若契约范围不清楚，标记 inconclusive，不能擅自把范围缩小成已排序列表。

线索连续两轮没有新增可复查证据则停用，预算只够一轮时无需凑满两轮。出现反例立即登记停用原因，并将依赖该线索的候选列入待重验；无关候选不自动否定。来源过期、无法读取或定位缺失时保留未知状态。

## 在宿主上实现独立性

记录 A/B/S/V/R 的真实实例 ID、可获取的模型标识和每次发送的输入清单。新实例应从规定输入启动；复制完整探索对话给验证者会泄漏不必要的结论与推理。不要把改名、切换人格提示词或 fork 完整历史等同于独立上下文。

宿主有子代理能力时使用其授权接口；没有时可以由用户提供独立会话。不要为了模拟子代理而擅自创建用户可见的新任务、调用付费 API 或升级模型。只有一个实例时交付结构化自检，并明确缺少独立审查。

本包不启动这些实例，不验证实例身份，也不为报告签名。AccessPolicy 只约束经过它的读写；真正隔离文件访问和工具权限需要宿主沙箱。可用的双 pass 标记不代表这些条件已经被机械保证。

## 修改和恢复

恢复时先读取原契约、累计账本、在途请求 ID、候选与审查版本以及待重验清单。先核对已返回结果再重试，不能重新创建一个满额预算掩盖先前消耗。

候选、输入数据、验收条件或关键假设变化时记录新版本，重新检查受影响的结论。模型更换需已有授权；区分仍适用于旧产物的客观证据与新模型生成的主张，不声称模型升级本身验证了任何结果。

`mark_model_change()` 记录待重验状态，但当前门禁不自动检查这份清单。宿主输出最终结论前必须同时核对：当前版本技术 pass、目标对齐 pass、实例独立、无未处理的重验需求。不得通过手工清标记代替实际检查。无法满足时交付具体未决项及所需下一次检查。
